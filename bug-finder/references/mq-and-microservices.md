# MQ / 微服务专项陷阱清单

## MQ

**消息丢失（P1 级重点）**
- 生产端：fire-and-forget 发送（不看发送结果/无 confirm/无回查）。
- Broker：无持久化、单副本、非持久化 topic。
- 消费端：先 ACK/自动提交 offset 再处理；处理失败也不 NACK → 消息永久丢失。

**重复消费与幂等**
- 至少一次投递语义下重复必然发生 → 消费逻辑幂等吗？识别：消费方法直接 insert/扣减，无唯一键、无去重表、无版本判断。
- 重点链路：下单、支付回调、扣库存、发通知（重复发通知是 P3，重复扣款是 P0）。

**顺序性**
- 多 partition/多消费线程下，状态流转类消息（创建→支付→发货）乱序 → 旧状态覆盖新状态。识别：生产端未按业务 key 分区，或消费端多线程无序处理。

**失败处理**
- 消费异常被空 catch 吞掉 → 消息"已消费"实际没处理。
- 无限重试：异常一直抛，无最大重试次数/死信队列 → 队列阻塞，后续消息全部延迟。
- 死信队列存在但无人消费/无告警。
- 消费超时未设，慢消费拖垮 broker 会话。

**DB 与 MQ 一致性**
- 事务方法内发消息：事务回滚但消息已发出 → 消费方处理了不存在的业务数据（P1）；正确姿势：事务提交后发送 / 事务消息 / 本地消息表。检查项目实际是哪种，再判定。
- 反向：先发消息再落库，落库失败消息已出。

**消息体演进**
- 生产方加字段/改类型，消费方反序列化兼容性；旧消息在升级窗口被新消费逻辑处理。

## 微服务 / 分布式调用

**超时与重试**
- 调用未设超时（依赖默认值或无限等待）→ 下游一慢，本服务线程堆积 → 雪崩，P1。
- 超时链路不对齐：上游 5s > 下游 8s（下游超时对上游无意义）。
- 重试风暴：重试无退避、无上限；多层链式重试放大（每层 3 次 × 3 层 = 27 倍流量）。
- 非幂等接口（POST 下单）配置了自动重试 → 重复下单，P1。

**熔断 / 限流 / 降级**
- 高危依赖（支付、库存）无熔断 → 故障传导。
- 降级逻辑本身的 bug：降级返回值与正常类型不匹配、降级里又调同一个已挂的服务。
- 对外写接口无限流；限流阈值与容量无关系（拍脑袋）。

**Feign / HTTP 客户端**
- 拦截器丢失透传头：鉴权 token、traceId、租户 ID 没传到下游。
- 负载均衡层重试 POST（Ribbon/重试配置对非幂等方法生效）。
- 返回值解包：下游错误码被当成功解析。

**网关与鉴权**
- 路由优先级/前缀覆盖导致请求打到错误服务。
- 鉴权白名单过宽（`/**` 放行、health 接口顺带放行业务路径）。
- 内部接口裸奔：依赖"内网安全"假设，无认证；SSRF 可达的内网接口。
- **水平越权（P0 级重点）**：接口按 id 查/改资源但不校验资源归属（`getOrder(id)` 不带当前用户过滤）——逐个写接口核对。
- 垂直越权：普通用户可调管理接口（网关鉴权与 服务内鉴权不一致）。

**跨服务数据一致性**
- 多服务写操作无最终一致性保障（无 saga/TCC/本地消息表），失败一半无补偿。
- 服务间冗余数据的同步机制缺失（A 库冗余了 B 的字段，B 更新后 A 不知道）。
