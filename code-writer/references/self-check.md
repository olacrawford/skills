# 完成后自检清单（Step 5 用）

逐项检查，发现问题当场修。带 ⚡ 的项有可执行命令，优先实际运行而不是目测。

## 通用清单

1. **编译/语法** ⚡ —— 跑构建命令（见下表），不许只靠 IDE 直觉。
2. **类型** ⚡ —— 强制转换、泛型、可空标注（TS strict / mypy / Java 泛型原始类型）。
3. **导入** —— 缺失、多余、循环 import；新文件 import 顺序符合项目习惯。
4. **空指针** —— 可空返回值的处理、链式调用、集合元素、map 查找 miss、Optional 误用（`get()` 裸调）。
5. **参数校验** —— 外部入口（HTTP/MQ/定时任务的入参）是否校验；协议边界不信任内部假设。
6. **异常处理** —— 是否吞异常（空 catch）、该不该向上抛、资源关闭（try-with-resources / defer / with / using）。
7. **边界条件** —— 空集合、单元素、0/负数、越界、超长输入、时区、浮点精度（金额用 decimal/整型分）。
8. **并发** —— 共享可变状态、锁粒度、幂等（重复请求/重复消费）、goroutine 泄漏、async 竞态。
9. **数据库** —— 事务边界是否覆盖多写操作；新查询条件有没有索引支撑；迁移脚本与实体定义同步；避免 N+1；大事务拆分。
10. **Redis / MQ** —— 序列化方式与既有数据兼容；key 设计与过期；消息重复消费的幂等；失败重试与死信路径。
11. **API 兼容性** —— 删字段/改类型/改语义对调用方的影响；响应结构是否向后兼容；版本策略。
12. **回归影响** —— 列出改动波及的既有行为，逐一确认未被破坏（靠 Step 6 的相关测试兜底）。

## 各语言可执行验证命令（⚡ 优先跑这些）

| 技术栈 | 编译/检查 | 静态/类型 |
|---|---|---|
| Java + Maven | `mvn -q compile` | （编译即主要检查） |
| Java + Gradle | `./gradlew compileJava` | `./gradlew build -x test` |
| Go | `go build ./...` | `go vet ./...` |
| Python | `python -m compileall <改动目录>` | `ruff check` / `mypy`（仅项目已配置时） |
| Node/TS | `tsc --noEmit`、`npm run build` | `eslint`（仅项目已配置时） |
| Rust | `cargo check` | `cargo clippy`（仅项目已配置时） |

注意：
- **只用项目已配置的工具链**，不擅自往项目里加 lint/mypy/CI 配置。
- 命令失败时原样记录错误输出，修复后重跑，全过程不静默。
